# 05 · 表情反应：空值也是状态

目标：最多选择一个反应，重复选择可以取消；键盘操作与点击等价。

阅读 [ReactionExample](../../../src/recipes/interaction-atlas/examples/ReactionExample.tsx) 和 [ReactionBar](../../../src/recipes/interaction-atlas/ReactionBar.tsx)。

## 提炼出的核心

```tsx
const current = value === undefined ? local : value
const next = current === id ? null : id
```

undefined 表示调用方没有控制状态，null 表示调用方明确控制为“没有反应”。不能用 value ?? local 代替第一行，否则 null 会意外回退到旧的本地选择。

不需要为每个反应维护一个 boolean。一个 string|null 就能表达“互斥选择或全不选”，也避免出现多项同时选中。

每项是原生 button，用 aria-pressed 宣告状态；符号本身 aria-hidden，清楚的名称来自 aria-label。方向键只移动焦点，Enter/Space 才切换选择，这与标签页的自动激活行为不同。

## 动手练习

1. 连点“喜欢”两次，观察状态先变为 like，再变为 null。
2. 选择喜欢后点“有启发”，前一项应取消。
3. 按方向键，确认只移动焦点；按 Enter 后状态才改变。
4. 修改 reactions 中的 label/symbol/color，组件逻辑不需要变化。

答案提示：如果取消后又出现旧选择，检查 undefined 和 null 是否混用了。触摸的子元素不应截获按钮命中，视觉悬停也不能使第二次轻点失效。

## 接入真实点赞时

本组件不登录、不计数、不发网络请求。父级收到 onChange 后，才根据实际用户身份发起请求并处理失败。不要把练习页里的本地选择显示成真实多人点赞数。

## 自检

选中/取消有可读状态，焦点可见，触摸连续两次能取消；减少动态后 aria-pressed 和状态文字仍保持反馈。后端授权不属于 aria 属性或按钮禁用能替代的功能。
